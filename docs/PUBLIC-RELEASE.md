## 已知限制

### Browser OpenAPI 与画布类型不同步

原始 Web 类型文件含 `CanvasDocument`、`CanvasNode` 等画布类型，而当前 Java Browser OpenAPI 缺少对应定义。按照当前 Java 契约重新生成会使画布相关 TypeScript 编译失败。

公开版保留原有可构建类型文件。因此 `npm run check:api` 会报告 `STALE`。这项一致性问题尚未解决；需要结合实际 Java 画布服务补全权威契约，不能通过手写第二套业务 DTO 或跳过检查解决。

### 原有 lint 问题

`CanvasWorkspacePage.tsx` 在 render 中使用 `Date.now()` 判断报价过期，触发现有 `react-hooks/purity` 规则。本次品牌与公开文档整理没有扩大范围修改画布报价行为，也没有放宽 lint 规则。

### 原三仓发布流程

部分历史 Gate 和部署脚本默认使用 `guanghe-backend` 目录及原有服务器布局。本合并仓库文档使用真实目录，并在跨端检查时显式传路径。生产发布需要基于自己的运行环境重新核对脚本、服务、版本来源与数据库。

本仓库没有附带模型和业务供应商凭据、公共测试账号、完整托管环境或可直接复用的生产发布承诺。原模块文档中的历史验收记录不等于本次公开版已经通过相同线上验收。
