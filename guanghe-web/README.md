# 光禾AI智能体框架 PC Web

## GEO 动画形象（2026-10-11）

- 使用用户提供的 `output/miyou-ai/frontend-handoff` 透明九帧素材，保留“光禾AI智能体框架”产品名称；直接替换 GEO 消息左侧的公司头像，撤除标题旁的独立摆件。非 GEO 智能体、用户头像和侧栏品牌 Logo 不变。
- 当前回复等待期间思考；收到正文增量后转为面向用户的轻呼吸“说话”姿态，直到收尾。回复成功播放完成动作；整篇文章/业务任务成功在其对应消息播放开心动作。失败、部分完成、停止和仅受理任务均不庆祝。TITLE/OUTLINE 子任务不算完整成果。
- 只有当前目标消息自动播放，guidance 与历史头像默认用静态图。消息尚未受理时使用 UI 等待行，不借用上一条头像；按稳定 run/task/article 标识追踪后再解析当前消息行，兼容临时时间线迁移到正式消息。空闲头像支持点击/Enter/Space 招手、冷却及局部鼠标倾身；忙时不被点击打断，减少动态设置会关闭呼吸与指针位移。
- 动画只消费状态，不发送消息、不启动监测、不扣积分。账号/会话/新建项目作用域隔离；历史首次加载、缓存恢复以及离开期间已完成的任务不重放成功动画。后台状态取任务事实，不信旧执行时间线。全文准备需本次打开后确实读到 RUNNING 才允许成功动效。
- PNG 通过 Vite 内容哈希打包，逐动作懒加载；保留原始裁剪校准。隐藏页面暂停；系统减少动态时使用静态帧，状态通过头像无障碍名称及原消息进度表达；静态头像下载失败显示“禾”字占位。装饰性 Canvas 不向屏幕阅读器逐帧播报。
- `/preview/geo-mascot` 为 DEV-only 浏览器交互验收入口，不发业务请求、不进入生产包。真实对话验收脚本 `scripts/live/geo-mascot.*` 使用明确授权的测试账号，并限制业务写入；视觉预览不能替代真实接口验收，接口验收不能替代 Canvas 视觉验收。

光禾AI智能体框架 PC Web 智能体平台及既有业务工作台的正式前端仓库。当前包含工程与认证基础、智能体库与安装管理、项目、经营资料、AI 对话工作台、任务中心、GEO 监测、图片创作、视频创作、文章与投稿、资产中心、积分账单，以及管理员用户管理和任务诊断展示层。已接入能力使用 Java Browser API；尚未接入的能力保留明确空状态或禁用入口。

## 2026-10-09：以客户项目为中心的产品精简

- 主导航只保留新聊天、智能体、品牌知识库、资产中心、自动监测、投稿。项目与历史聊天保留，任务记录收进账户菜单；积分账单与通知入口不变。
- “自动监测”直接展示计划管理，不再附带旧工作台的八项页签；新建计划、查看执行任务、查看报告保持可用，历史 GEO 深链不改。
- 聊天只选择一次所属项目，不再提供经营空间、商品绑定或空上下文侧栏；有任务时才显示“任务进度”抽屉。文章/阶段报告仍使用右侧画布。
- 新聊天切换客户项目或智能体，保留输入文字，清除上一范围的报告引用、图片附件与未完成的附件状态。上传中禁止切换；服务器仍负责项目、资料、记忆、成果的隔离。已有聊天沿用冻结归属，不重新绑定历史商品。
- 品牌知识库统一管理公开品牌名称、资料、对话沉淀的事实和表达偏好。旧版偏好只读折叠保留，不再提供两套并行写入入口；无记录时不展示历史区域。
- 品牌知识库的“品牌档案”展示四项最低资料：对外品牌名称、主营业务、实际经营／服务范围、目标曝光地域；推广重点与关键词／搜索需求是选填。允许逐项手动修订，也读取对话沉淀的同一项目有效记忆；显示来源和版本，缺失或读取失败不会混为一谈。资料完整度只是提示，不是全站准入或执行授权。公开名称继续使用项目 GEO 对象，其他字段复用记忆 API，不由内部项目名推断。切换客户会放弃未保存草稿，不能将上一客户内容提交到下一项目。
- 固定档案字段删除后保留无内容的删除标记；“重新填写”从空白开始，仅在用户重新输入并保存时以当前版本、`restore: true` 调用原记忆更新接口，不恢复旧值、不重复创建固定键。并发修改仍须核对当前版本后再保存。
- 资产中心按客户项目管理文章、图片、视频，去掉商品筛选。无项目创作仍保留个人素材，不自动挂到其他客户。生成满意后直接投稿，或保存到资产中心编辑、配图后投稿，两条路径均保留。
- 旧工作台 `/app/workbench` 重定向至聊天首页，并保留 URL 参数。旧生图、视频、三阶段写作和经营资料不再列为主导航入口；历史任务/文章/报告深链继续兼容。本批未删除数据库记录，也未重命名内部 `spaceId` 字段：现有项目和经营空间使用同一客户归属实体。
- “制定品牌优化方案”仅预填，不因点击入口就提交监测；已有未发送内容不会被推荐输入覆盖。固定监测、引用报告、阶段报告与最终投稿确认入口保留。

本批验证以真实 React 页面交互配合 Browser API stub 为主（无模型、搜索或媒体费用）：`project-first-chat.integration`、`project-library-simplification.integration`、`platform-navigation.integration`、`geo-period-report.integration`，并回归公开品牌名称、任务与投稿入口。此说明不代表已经部署或完成线上人工验收。

## 智能体平台第一批

- `/app` 为新任务入口；`/app/agents` 提供“智能体库 → 添加 → 我的智能体 → 使用”，只消费 Java 返回的目录，不在生产前端植入演示智能体。内部摘要夹具是否可见由服务器配置与授权决定。
- 首条消息才创建会话，并传入显式选择的 `installationId` 和可选 `projectId`。项目只需名称、无需品牌或商品；开始任务不要求创建项目。会话显示智能体名称和所属项目，服务器仍冻结智能体版本；切换智能体另开新聊天，不更新旧会话身份或所属项目。
- 安装支持添加、启用/停用、移除及中文加载/空/错误/重试状态。未安装时提供明确“添加智能体”入口，不自动安装；新任务仅使用已添加、已启用且当前定义为 `PUBLISHED` 的智能体。移除不删除项目、历史会话和成果。升级动作不在本批接口范围内，旧会话只显示保存的版本。
- 232px 单侧栏包含主导航、项目及嵌套会话、未归入项目的最近任务、固定账户区；窄屏通过导航按钮展开。项目列表失败时仍提供该项目历史会话的降级入口。
- 旧工作台 `/app/workbench` 重定向到 `/app`；“更多功能”及其中重复入口已移除。旧 `/app/chat` 会话与报告深链继续兼容，任务记录可从账户菜单查看。
- 左侧独立“投稿”入口为 `/app/submissions`，提供媒体目录和投稿记录；聊天新生成的文章可在右侧画布查看、保存和确认投稿，既有文章工作台继续兼容。
- 早期资料库复用图片/视频资产中心；后续资料、报告和对话能力分批接入，具体范围以下文对应章节为准。普通 GEO 对话的本轮范围见下方 M1 说明，不能再统一归为“监测重构未交付”。既有显式业务入口与付费确认保持兼容行为。

定向验证：`npm test -- src/test/agent-platform.integration.test.tsx`（包含仅测试配置返回的非 GEO 智能体）。接口类型统一由 Java canonical Browser OpenAPI 生成，不另写业务 DTO。

### 2026-10-08：原生 GEO 对话 M1 范围

普通 GEO 自然语言消息已接入原生 Agent Loop，候选验收链路是：不预建项目，在聊天中补充品牌资料 → 明确要求后发起首次监测 → 查看真实报告并追问 → 新聊天召回已沉淀的品牌资料与表达偏好。执行仍由 Java 校验权限、预算和任务结算。显式监测按钮（`monitorAction`）与历史全文准备结果保留兼容行为；新增写文章入口已改为普通自然语言发送，具体范围见下方“资料、全文准备与自动监测”。不能以 GEO 对话结果证明全文创作、媒体发布、完整记忆治理或自动上下文压缩整体通过。功能验收以真实账号的对话、任务和报告证据为准；实际页面的人工视觉与交互验收尚未执行。

## 投稿中心

- 无需先创建文章即可查看媒体目录。媒体名称、目录状态、价格范围与分页使用 Java 真实接口；参考金额按人民币元展示，积分保持服务端原值，另列显示。同步时间和参考价有效期用于判断目录快照新鲜度，不代表实时上游可投或全局投稿开关已开启。
- 投稿记录按单家媒体订单展示，支持状态筛选、分页、查看详情与原文章。金额和积分取下单快照，不能作为最终消耗或退回金额；结算以积分账单为准。发布回链去重并展示全部安全 HTTP/HTTPS 链接；已发布但未返回链接时明确提示，不伪造回链或 AI 收录结果。
- 本页只有只读查询和站内导航，不创建报价、任务或订单。待核对记录可刷新状态，不能直接重投；“选择文章投稿”进入资产中心文章页，最终下单仍须确认文章、媒体与最新报价。列表和详情复用有界轮询，后台页面不持续轮询；切账号清除选中详情与筛选，缓存按账号隔离。
- 目录或详情读取失败显示错误，不把失败伪装成空记录，不继续展示已失效的缓存详情。筛选栏允许换行，目录表格局部横向滚动，投稿卡片中长编号和链接允许换行。

定向验证：`npm test -- src/test/submission-center.integration.test.tsx`。普通用户真实接口已读取非空媒体目录两页；测试账号没有投稿记录，真实回链和外部发布不属于这次只读验收。

## GEO 结果与聊天衔接

- 每轮回复按 Run 归并进度，迟到的发送受理回执复用已有助手进度；服务端快照与旧浏览器缓存恢复保持相同身份、阶段与耗时。独立后台任务继续按任务身份展示，回复完成后不会残留第二个等待框。
- 原生对话的思考/处理阶段使用真实 `agent.progress`，过程可折叠查看；只展示受控阶段标签与工具状态，不展示供应商原始推理、提示词或工具原文。正文收到 `message.delta` 后立即按 Markdown 渲染，不使用假打字动画；`replace: true`（包括空串）替换当前预览，用于撤回工具调用前的临时说明。正文缓存按事件序列与服务端快照高水位合并，旧快照不能复活已撤回内容，重连不会重复追加。停止/失败保留已经收到的正文并停止输出指示，后台任务位置与文章右侧画布不受此机制影响。
- 回复过程默认收起，摘要展示最后收到的真实阶段及服务端样本计数；展开状态在进度、完成和失败事件之间保持。已结束或已进入后续阶段的过程不继续显示加载动画，也不自行补成成功。待补充信息、部分完成、任务等待确认与执行失败分别展示；过程中的耗时不触发屏幕阅读器逐秒播报。最终报告、文章、图片和视频继续使用既有成果卡片操作。
- 聊天不再固定展示“查看已有 GEO 趋势”“查看竞品洞察”及一键商品分析入口；已有成果卡仍可进入对应结果。“制定品牌优化方案”等推荐只预填，不自动提交。有未发送内容时保留原输入。这不限制普通 GEO 消息使用原生 Agent Loop。
- 报告详情“带这份报告问 AI”进入 `/app/chat?geoReportId=…`。页面先读取报告及专题校验可访问范围，再采用报告冻结的经营空间和商品，只预填通用问题，不自动创建会话、发送消息或启动分析。
- 输入框“＋ → 引用监测报告”按明确选择的项目查看跨专题历史报告（时间、专题、平台、状态），已有项目会话锁定所属项目；没有项目时必须先选择项目，不能列全账号报告。每次最多引用一份，选择后重新核对报告冻结范围，已归档或不可访问的报告不能引用；选择本身不填问题、不发送消息、不发起监测。
- 引用以输入框内“当前引用”标签展示，可查看、更换、移除；在当前对话中持续可见，后续普通消息显式传同一 `geoReportId`，不因连续追问而换成最新报告。成功发送只清文字和图片；发送失败保留输入与引用。用户消息保留可点击的固定报告链接，历史名称缺失时使用通用名称，不为每条历史消息重新查询报告。移除、切换会话、项目、经营空间、商品或账号会解除当前引用，刷新不会从历史消息猜测恢复；已有会话的混合深链须通过加号明确重新选择，不静默附带报告。
- 报告读取中或失败时禁止半绑定发送；不覆盖已有输入。报告来源不能与图片附件混发。浏览器不将整份报告、原始答案或导出 Markdown 拼接到提示词；Java 每轮重新验权并提供有界只读快照。
- 无明确报告时，由 Java 决定当前商品是否有唯一可用专题；多专题或缺少资料时引导选择，不由 Web 猜测最新报告。趋势与竞品结果按钮只使用真实任务报告及专题编号；Markdown 沿用既有 URL 安全规则，链接文本本身不是授权依据。
- 完成的助手回复通过 Java 保存的 `content.geoContext` 展示本条回答实际依据的报告与后续动作；刷新读同一快照，不能从 Markdown、流式正文或“最新”列表猜报告。多专题入口只导航，用户选报告后再转聊。
- 聊天报告卡的“引用报告写文章”只读取并绑定这份真实报告、预填可修改的写作需求；用户发送后走普通 Agent Loop，不新增标题确认草稿或全文授权弹窗，也不自动投稿。已有输入或图片先保留，不自动覆盖。报告须未归档、有有效样本、采样终态并完成智能解读；点击时重新读取原报告并由服务端再次核验。历史标题草稿与兼容文章记录继续可查。
- 上述报告来源入口本身不分析历史竞品、不确认候选、不改自动计划，也不因打开页面就发起监测；后续普通 GEO 消息是否执行监测由原生 M1 链路依据用户请求决定，既有显式操作仍可从相应 GEO 页面进入。

## 前端发布与白屏恢复

前端采用带内容哈希的分包。已经打开的浏览器可能跨过多次发布才访问一个懒加载页面，不能仅保留上一个版本的资源。

- 切换 `current` 前，在部署锁内运行 `python3 scripts/retain_web_assets.py /opt/zhixiaohe/web/releases /opt/zhixiaohe/web/retained`，保留所有已保留发布目录的静态资源。脚本不删除发布目录、不覆盖同名不同内容文件，发现冲突先失败。
- 必须使用当前仓库版本的留存脚本，不能复用只识别 Git SHA 目录名的旧脚本。现在同时支持安全的具名版本目录；可先加 `--dry-run` 只读检查版本、资源和待补文件。拒绝符号链接及特殊文件，完成全量冲突校验后才补齐资源。
- Nginx 的现有站点 `server` 内用 `deploy/nginx-static-locations.conf` 替换原来的 `location /`。当前资源缺失时查归档，仍不存在则返回 404；禁止把 JS 请求回退成 HTML。HTML 不缓存，带哈希的资源可长期缓存；不覆盖已有安全响应头或 API/回调路由。
- 更新 Nginx 前备份配置，`nginx -t` 通过后才 reload。验收必须检查旧分包的内容类型为 JavaScript、缺失分包为 404、页面 HTML 为 no-cache，不能只看 HTTP 200。
- 路由错误边界接住分包加载和页面渲染异常，显示安全的“重新加载页面”入口，不展示堆栈或 traceId，不自动刷新、不重新提交任务。已提交付费任务以服务端和任务中心为准。

定向验证：`python -m unittest discover -s scripts -p test_retain_web_assets.py -v`，以及 `npm run test -- src/test/page-error-boundary.test.tsx src/test/geo-plan.integration.test.tsx src/test/auth.integration.test.tsx`。

## 认证流程

Java 仓库中的以下文件是当前浏览器认证契约的唯一权威源：

```text
D:\coding-project\guanghe-backend\src\main\resources\contracts\openapi\browser-openapi.yaml
```

运行 `npm run generate:api` 会生成 `src/api/generated/browser-api.ts`。业务 DTO 不手工复制；运行时客户端使用生成类型并解析 Java 的统一成功/错误包络。

Java 与 Web 使用独立 Git worktree 协作时，可设置 `JAVA_BROWSER_OPENAPI` 指向当前 Java worktree 的
`browser-openapi.yaml`；未设置时仍使用默认 sibling 路径。生成和校验必须使用同一个契约文件。

`npm run check:api` 会在临时目录重新生成并与已提交文件比较；发现 Java Browser OpenAPI 已变化但生成类型尚未同步时以非零状态退出，不修改工作区。

登录成功后保存 `accessToken` 与 `expiresAt`，并立即按 Java 返回的 `user.role` 分流。页面刷新时读取本地 Token，再调用 `/api/v1/auth/me` 恢复会话；不会通过解析 JWT 决定权限。第一版没有 Refresh Token。

退出时调用 `/api/v1/auth/logout`；无论服务器调用是否成功，都会清除本地 Token 和用户状态并返回登录页。受保护请求返回 401 时清除 Token 并进入登录过期流程；403 显示无权限状态；429 与 503 在登录页显示安全提示。错误视图可以显示和复制真实 `traceId`，不会展示堆栈、完整响应体或内部信息。

## 数据与安全红线

- 生产组件不硬编码用户、积分、商品、经营空间、任务、GEO 报告或运营统计。
- Figma 中的商品、任务、积分和图表仅是视觉演示，不进入运行时数据。
- 后端没有数据时显示真实 Empty；接口失败时显示真实 Error；接口未实现时明确禁用。
- 不使用 `setTimeout` 模拟请求，不把 JSON 当业务接口数据，不在正常开发或生产运行时启动 MSW。
- 测试仅在 `src/test` 或 `*.test.*` 中使用最小 fetch Stub/fixture，生产组件不导入测试 fixture。
- 密码和 JWT 不进入 URL，不输出到 console，不写入错误视图。
- Snowflake ID 始终保持字符串。

- GEO 聊天底部统一为“写文章”：仅预填自然语言需求，用户可以修改后发送。普通发送及报告引用写作走同一入口，不再创建 `articlePreparationMode: ARTICLE_FULL_V1` 新请求，也不要求先确认生成。Java 注入可信 `content.articlePreparation` 引用；聊天只读取真实准备记录显示阶段和结果，不从模型正文猜文章编号或把工具受理当成完成。
- 自动全文子任务通过 Java `PaidTask.articlePreparationId` 标识，聊天不再把其中 TITLE、OUTLINE 的完成误展示为独立成稿或人工确认卡；历史独立文章流程不改写。生成时自动打开右侧文章画布，窄屏使用全屏抽屉。“查看文章”可重新打开，历史成果路由 `/app/article-preparations/:preparationId` 保留。正文预览只读取 Java 持久化的真实流式快照，事件触发更新并以有界轮询支持刷新恢复；按执行号和序号防止旧预览回退，不用前端逐字动画冒充流式。最终成功只由准备任务与正式文章状态确认，失败、超时、读取失败不当作成稿或自动再次收费。
- 完成稿渲染安全的 `bodyHtml`，保留标题、段落、列表等排版，不用丢失分段的 `bodyText` 当 Markdown。完成后明确提供“投稿”和“保存到资产中心”；投稿先在当前画布查看真实媒体和费用，只有最终“确认投稿”会创建投稿任务。资产中心“文章”页仅列用户明确保存的文章，使用同一 `articleId` 和正文版本，不复制内容。整篇编辑使用固定版本 Tiptap 3.31.4，支持撤销/重做、标题/正文、粗体/斜体/下划线/删除线、列表、引用、安全 HTTP/HTTPS 链接及既有表格编辑；不展示服务端不能保存的字号、颜色和对齐按钮。
- 编辑器“图片”菜单包含“本地文件上传”和“从资产中心选择”，复用当前项目 READY 图片及本地 PNG/JPEG（单张不超过 20 MiB）。打开菜单时保存光标，并随编辑映射位置；异步完成后插入原光标，不覆盖选中的正文。图片只存 `figure[data-asset-id]` 与说明，临时下载地址不写入正文。最多 10 张不同图片，删除图片同步关联；粘贴不接收任意远程图片或脚本。底部提供字数、预览、保存修改和“保存并投稿”；后者先保存当前版本再进入推荐，不直接发布。
- 图文保存按“必要时补齐新旧配图并集 → 保存正文 → 清理旧配图关联”执行，每一步使用上一请求返回的版本。新旧并集超过 10 张时不发请求，明确提示先删除旧图并保存，再添加新图。每个已确认步骤同步父级缓存；部分失败保留修改并明确哪些步骤已完成，不假装事务回滚。超时或版本冲突需核对最新文章，不自动覆盖；退出编辑重新读取最新版。
- 保存目录标记不改变文章正文版本；文章、目录和媒体建议缓存按账号与文章版本更新。聊天和资产中心读取同一正文。未保存草稿暂存在当前标签页 `sessionStorage`，按账号和文章隔离、最长恢复 24 小时，保存或明确放弃会清除；刷新有离开提醒，再次打开编辑显示恢复提示，服务端已变更则明确提示版本冲突。存储不可用时警告先保存再离开。含图文章可保存和编辑；投稿仅认可 Java 投影的 `capabilities.supportsImages=true`、明确图片计费方式与数量限制，不从供应商文字自行推断授权。直接投稿和保存编辑后投稿共用同一推荐卡，展示本稿图片数、基础费用、图片附加费和含图总价；免费/已含、按张、按篇的精确费用均读取 Java `articlePricing`，前端不自行估费。目录只展示基础价，最终确认读取报价草稿中的本稿明细；未知图费或缺少本稿报价时不能确认。最终报价与用户看到的图片数、计费方式、金额或积分任一不一致则停止，不静默下单。图文渠道未核验时保留稿件，不要求删图、不创建订单。页面人工视觉与交互验收仍需用户完成。
- “确认投稿”是唯一发布确认。该次点击核对正文版本和实际报价，再创建精确快照并提交；价格、版本或登录状态变化停止提交。已受理不标记成已发布，发布记录及回链仍由投稿专栏显示。修改/删除资料不改写旧成果，成果页提示生成时来源已变化。
- GEO 报告 MD、PDF 导出均读取 Java 已保存报告，不额外调用模型或重新监测。报告写作深链继续保留冻结报告引用，新写作不再启用旧全文模式。
- 自动监测支持固定每小时频率（`HOURLY`，时区与时间分钟作为锚点），恢复草稿保留原频率。定时计划只执行监测，不定时生成或发布文章。
- `/admin/platform` 管理已发布定义的状态/可见范围、计划暂停/恢复/执行时段，以及知识资料和偏好的处理元数据。变更携带原状态、定义 hash 或计划版本；不读取用户私有正文。原有用户、账务、媒体、任务和日志管理继续使用原路由。
- 本次原生文章入口及准备结果卡执行 API 类型生成、类型检查、lint 与构建检查；未以旧页面链路测试代替真实功能验收。真实模型成稿、最终投稿和人工页面验收由对应验收证据确认，不能仅据构建成功宣称已通过。

### GEO 诊断报告：单卡六步翻页与后台交付

- GEO 聊天加号“诊断报告”直接创建或恢复当前项目聊天的诊断草稿。每份诊断只显示一张等高卡片，顶部 `‹ 1/6 ›` 左右翻看已到达步骤，长内容在卡片内上下滚动；刷新恢复服务端当前步骤。六步依次为品牌名称、资料确认、最多五个同类品牌、可见度问题、品牌口碑问题、平台与报价。品牌公开资料及同类品牌均带可核对来源与真实资料缺口提示；用户确认前仅作为诊断草稿，不覆盖项目品牌知识库。
- 翻页仅为本地浏览，不保存、不生成、不提交；“确认并继续”才推进流程。查看历史页时保留当前未保存的输入，仍持续读取后台进度；返回修改前置步骤后，失效后续步骤不再可翻到。界面按聊天与诊断编号折叠纯诊断历史消息，普通消息和不同诊断保持独立，服务端历史快照不删除。
- Java 保存草稿版本及不可变历史卡片，只有当前步骤最新卡片可编辑。重新生成先保存手动修改，再由服务端保留已编辑或手动添加项；回改前置资料会重新准备后续内容。生成期间的聊天输入可正常使用；卡片不是普通 Agent Run，也不会制造第二条聊天回复进度。
- 默认五个发现型问题、三个目标品牌口碑问题，可分别编辑、增删或重新生成。发现型问题排除目标与已选同类品牌的名称和品牌词；口碑问题显式询问目标品牌。两组各至少一个、合计三至十个，平台选择与报价只读服务端实际可用平台及费用。
- 最后卡只有核对当前配置的服务端报价、预算与有效期后，才允许用户明确“提交诊断并生成 PDF”；服务端未开放执行时仍明确禁用。默认五个发现型问题、三个口碑问题，每平台一次采样；七个平台为 56 样本。若真实单次预算为 50，明确阻止并解释，不自动降低问题/平台或提高账户预算。
- 正式提交使用账号、项目、聊天、诊断隔离的稳定请求身份；丢回执保留该次身份，只由用户点击 GET 核对或重试同一次提交，不自动重下单。提交后六卡配置冻结。Java 保存后台任务与递增交付 revision；聊天仍可正常输入发送，刷新后恢复采样、分析、PDF 的真实状态，不创建普通回复 Run。
- 独立 `/app/geo/diagnostic-reports/:diagnosticId` 读取诊断与报告的任务归属，原 `/app/geo/reports` 增加“监测报告 / 诊断报告”分栏；诊断列表必须显式选择客户项目，只请求服务端 `submittedOnly` 的正式交付记录与分页。账号登录 revision、项目、聊天与业务编号隔离缓存，读取失败不展示旧客户数据，迟到 GET 不能回退已确认版本。
- 在线详细报告展示服务端采样覆盖、分平台自然可见度 SVG 图、独立口碑指标、带证据的发现和优化建议、内容选题蓝图及公开资料来源。失败/缺失不计成零，无有效发现型回答不计算可见度比例。分析摘录与分页完整回答明确区分，不以摘录冒充原文；单次样本不代表市场份额、整体口碑或已达到优化效果。
- `READY` 仅表示 PDF 已交付，必须同时说明采样结果。全部监测失败时显示“未获取有效样本”和失败说明 PDF，不伪造结论或庆祝诊断成功；结算与释放积分使用服务端记录。分析/PDF 失败的“恢复生成报告”只恢复交付，不重新监测或收费。
- PDF 下载必须携带当前不可变 `reportVersion`，登录授权读取私有 HTTPS 短期下载链接，并核对预览版本与文件名后才触发下载。不缓存/输出签名地址，不向存储域传登录 Token。报告的“回到聊天继续优化”只回到原聊天，不自动发送或创建任务；后续 GEO 自主读取报告由 Java 验权。
- `geo-diagnostic-cards.integration.test.tsx` 验证六卡交互、手动修改保留、历史快照、项目隔离与迟到响应、生成失败不阻断聊天、显式新建、品牌词边界和报价失败清除旧价格。`geo-diagnostic-delivery.integration.test.tsx` 使用真实 React 组件和 Java HTTP stub 验证单次提交、丢回执恢复、预算/过期报价阻止、配置冻结与普通聊天、独立指标、全失败、完整原文分页、交付恢复、精确版本下载、权限拒绝和迟到登录/客户隔离。生产类型由 Java Browser OpenAPI 生成；这些测试不证明真实搜索/模型、PDF 像素或人工点击已验收。

### 2026-10-23：诊断报告咨询式呈现
